# Мартышкин труд Runner — канон уровней, структура и логика

**Версия документа:** 2026-06-07  
**Назначение:** единая структурная база для Codex, ручной разработки, генерации ассетов, level design, UI, QA и дальнейших ТЗ.  
**Статус:** каноническая карта уровней v1.0.

---

## 0. Зачем нужен этот документ

Этот файл фиксирует канон 15 уровней игры **«Мартышкин труд Runner»**.

Документ нужен, чтобы:

1. Codex не придумывал уровни заново.
2. Генерация PNG, платформ, препятствий, UI и фонов шла по единой структуре.
3. Каждый уровень имел собственную тему, юмор, визуальный язык и gameplay-логику.
4. Все папки, конфиги и ассеты назывались инженерно предсказуемо.
5. Игра не превращалась обратно в кашу из случайных картинок.

---

## 1. Глобальный канон мира

**Мартышкин труд** — сатирическая runner-игра про мир, где труд существует не ради результата, а ради отчёта, плана, проверки и вида занятости.

Главный закон мира:

> Если работа выглядит важной, значит она почти выполнена.  
> Если есть банан, значит есть KPI.  
> Если есть акт, значит никто не виноват.

Игрок — примат, который бежит через разные слои системы:

```text
стройка → логистика → офис → джунгли/ферма → инспекция → фабрика → архив → реактор → аудит → ночная смена → обучение → башня согласований → министерство-фабрика → сердце труда
```

---

## 2. Глобальная структура gameplay

### 2.1. Жанр

```text
2D runner / platform runner
```

Игрок бежит слева направо, собирает предметы, прыгает, делает рывок, избегает hazards и выполняет “план” уровня.

### 2.2. Основные сущности

```text
Player / Примат
Platforms
Collectibles
Powerups
Hazards
Background layers
Progression props
HUD
Achievements
Dev Mode
```

### 2.3. Collectibles

```text
банан        = +1 к плану
фиговый лист = +2 к плану
кокос        = +5 к плану
```

Дополнительные предметы: каска, жилет, ботинки, магнит, щит, кофе, чертёж, пропуск, печать, ключ, энерго-капсула.

### 2.4. HUD

Если в цель уровня входят не только бананы, использовать:

```text
ПЛАН X/Y
```

`BAN` допустимо только для старого режима, где считаются исключительно бананы.

## 3. Глобальный визуальный контракт уровней

Каждый уровень обязан иметь:

```text
уникальную тему
уникальный фон
уникальные платформы
уникальные hazards
уникальные таблички/шутки
уникальные progression props
собственный UI-card/icon в выборе уровня
```

Нельзя:

```text
использовать одинаковые платформы на всех уровнях
мешать 5–6 тем в одном уровне
ставить офисные столы на ферму без гэг-обоснования
использовать весь PNG-лист как одну текстуру
делать фон активнее gameplay
делать hazards похожими на декор
```

---

## 4. Инженерный фоновой контракт

На каждый уровень рекомендуется:

```text
5 base PNG layers + 3 progression prop sheets = 8 фоновых/прогрессионных PNG
```

### 4.1. Base layers

```text
levelXX_bg_far.png
levelXX_bg_mid.png
levelXX_bg_near.png
levelXX_track_backdrop.png
levelXX_grade_fog.png
```

### 4.2. Progression props

```text
levelXX_props_start.png
levelXX_props_mid.png
levelXX_props_end.png
```

### 4.3. Runtime-прокрутка

Один PNG-слой создаётся в 2–3 runtime-сегментах. Не создавать отдельные PNG только ради повторения.

```ts
worldDistancePx += worldSpeed * dt;
offset = (worldDistancePx * parallaxFactor) % effectiveWidth;
segmentX = Math.round(-offset + segmentIndex * effectiveWidth);
```

### 4.4. Parallax factors

```text
BG_FAR          0.08
BG_MID          0.20
BG_NEAR         0.42
TRACK_BACKDROP  0.85–1.00
GRADE_FOG       0.00
```

## Краткое описание

Стройка, где план есть, смысл не завезли.

## Тематика

строительная площадка в джунглево-горной зоне

## Роль в лоре

Вход в Мартышкин труд. Игрок впервые видит главный закон мира: важнее не результат, а бодрый вид занятости.

## Визуальный язык

- краны
- строительные леса
- доски
- трубы
- бетономешалки
- каски
- конусы
- таблички

## Платформы

- доски на лесах
- кирпичные подпорки
- ящики с инструментами
- бетонные блоки
- подвесные подмости

Инженерное правило:

```text
2–4 типа основных платформ
2–3 альтернативные платформы
1–2 редкие специальные платформы
```

Платформа должна иметь отдельную collision-форму, а не полагаться на визуальный контур PNG.

## Hazards / препятствия

- падающие бананы
- кирпич с душой
- смета кусается
- бетон с бананом
- табличка «Не стой под грузом»

Каждый active hazard должен иметь минимум два признака:

```text
контур
warning accent
короткая warning-анимация
уникальный силуэт
понятная collision-зона
```

## Collectibles / бонусы

- банан
- фиговый лист
- кокос
- каска
- жилет
- магнит

Базовая экономика:

```text
банан = +1
фиговый лист = +2
кокос = +5
```

## Прогрессия фона по мере прохождения

- вход на объект
- центр стройки
- большой баннер «Мартышкин труд»
- зона хаоса с краном

Рекомендуемые progression assets:

```text
level01_props_start.png
level01_props_mid.png
level01_props_end.png
```

## Таблички и юмор

- «Каска есть. Плана нет. Бананы есть.»
- «Осторожно: идёт работа, никто не знает зачем.»
- «План на день: копать, носить, катать, повторять.»

Правило: фоновые таблички должны быть смешными, но не должны выглядеть как активные hazards.

## Аудио-настроение

```text

collect: короткий смешной звук
hazard: резкий, но не раздражающий cue
success: короткий мартышкинский сигнал
```

Ambient должен соответствовать теме: **строительная площадка в джунглево-горной зоне**.

## Acceptance criteria

Уровень принимается только если:

```text

платформы соответствуют теме
hazards не похожи на фон
фон не спорит с player lane
collectibles не забивают экран
нет белых пятен вокруг PNG
нет английских надписей, если они читаемы
```

# 8. Codex rules

1. Считать этот документ каноном.
2. Не менять названия уровней без отдельного согласования.
3. Не смешивать темы случайно.
4. Не использовать ассеты из одного уровня как основу другого без причины.
5. Все новые PNG называть по схеме `levelXX_role_description.png`.
6. Все новые изменения сверять с этим документом.
7. После каждой правки указывать, какой уровень и какую часть канона она затрагивает.

# 10. Финальный принцип

Мартышкин труд — это не просто “обезьяна собирает бананы”.

Это мир, где:

```text
стройка превращается в логистику,
логистика в бюрократию,
бюрократия в проверку,
проверка в фабрику,
фабрика в архив,
архив в реактор,
реактор в аудит,
а всё вместе — в сердце бессмысленного, но очень важного труда.
```

Если новый ассет, уровень, текст или механика не поддерживает этот принцип — он не канон.
